# v1.2 — 彻底迁移 LiveKit SFU 架构与推流逻辑剥离优化

**日期**: 2026-04-08  
**分支**: `sfu-livekit`  

## 概要

彻底废弃了初期低效且难以穿透 NAT 的点对点（P2P）WebRTC 直连架构，全面拥抱 **LiveKit SFU** 强力媒体服务器，同时对底层推流捕获（Publisher）架构进行了大刀阔斧的解耦重构。经过本次更新，多端跨网络访问的连接卡死难题（如 `waiting for stream...` 或由于网络策略导致的 UDP ICE 失败）被完美终结，且系统真正实现了 SFU 一对多的轻量分发。

## 变更明细

### 核心架构与容器编排 (`docker-compose.yml` / `livekit.yaml`)
- **新增** 引入 `livekit-server:latest` 服务作为媒体流的单点转发核心（SFU）。
- **优化** LiveKit 强制开启 Docker 网络模式为 `network_mode: "host"`，使其完美继承宿主机内网（`192.x.x.x`）及桥接网卡参数，免除繁琐端口映射，解决 UDP Candidate 收集被局域网 NAT 隔离而导致的推流或收流失败问题。
- **废弃** 移除 `livekit.yaml` 层面硬编码的 `node_ip`，启用原生的全局接口监听与智能候选回放（Loopback/LAN candidate）。

### 后端架构解耦与重组 (`tab_publisher.py` / `tab_manager.py`)
- **废除** 彻底删除并瓦解了过度耦合的历史文件 `webrtc_bridge.py`。
- **重构** 剥离推流动作，构建了独立存在的 `TabPublisher` 对象。现在，当某个 `Tab` 被新建出来时，Publisher 会与其生命周期直接绑定，**且全局只调用一次** `navigator.mediaDevices.getDisplayMedia`，将唯一流推给 LiveKit。极大缓解了后台容器 Playwright 开销，真正具备 SFU 的 1-to-N 服务能力。
- **重构** `ws.py` 已被降级为纯粹的“交互控制器”：它不再处理任何流注入逻辑，只需一个死循环接收前端键鼠操作指令并转发到 `TabManager` 的页面接口。

### 代理与安全跨域 (`ws_proxy.py`)
- **新增** 实现本地高速的 `ws_proxy.py` HTTP/WebSocket 代理服务，将 `http://127.0.0.1:8085/livekit-proxy` 直连到外部暴露的 Host IP 上。这是防范 Chromium `Mixed Content` HTTPS 安全协议阻断的护城河，让跑在 Google、YouTube 等任意安全页面的无头组件，都能在同源 `127.0.0.1` 黑魔法里完美推流。

### 前端极简重构 (`viewer.html`)
- **重构** 清理掉前端陈旧繁杂的 WebSocket `ready` 自建信令。现在前端只依赖官方规范的 LiveKit JS SDK。
- **优化** 加载页面时，前端会自动获取 `access_token` 并静默呼叫 LiveKit Room。
- **新增** `trackUnsubscribed` 和 `trackSubscribed` 监听。当上游网页开始重定向或者刷新时，前端原生的 `nav-overlay` 缓冲层会自动呼应出现与消失。

### 工具依赖 (`scripts/`)
- **新增** `scripts/download_sdk.sh` 用以自动获取和锁定原生 LiveKit SDK 的运行时 JS 构建文件，支持系统在纯粹离线环境的高速分发。
