# v2.0 — Pion Go SFU + 事件驱动导航 + RTP 序列号重写

**日期**: 2026-04-08  
**分支**: `sfu-livekit` → `sfu-pion-optimize`  

## 概要

彻底废弃 LiveKit Server，改用基于 [pion/webrtc](https://github.com/pion/webrtc) 的自建 Go SFU。采用 **ICE Lite + NAT 1:1 + UDPMux 单端口** 架构，配合 **事件驱动导航 overlay** 和 **RTP 序列号/时间戳重写**，实现页面跳转时 subscriber 零重连的无缝流切换。

## 为什么替换 LiveKit

| 问题 | LiveKit | Pion SFU (本版) |
|---|---|---|
| ICE 模式 | Full ICE（需双向连通） | ICE Lite（服务端被动响应） |
| Chrome mDNS 隐私 | 致命 — host candidate 被隐藏 | 无影响 — 不需要知道浏览器 IP |
| 路由器级代理 | srflx 不可达 → 断连 | 无影响 — 浏览器主动连服务端 |
| Docker bridge | 需要 hairpin NAT | 标准 DNAT 即可 |

## 变更明细

### 新增：Go SFU 服务 (`sfu/`)
- **`sfu/main.go`**: ~330 行 Go 代码
  - ICE Lite + NAT 1:1 + UDPMux 单端口
  - HTTP 信令 — `POST /offer?room=xxx&role=pub|sub`
  - **RTP 序列号/时间戳重写** — publisher 重连时自动偏移 seq/ts 保持连续性，subscriber 无需重连
  - 每 2 秒周期性 PLI 确保关键帧持续流动
- **`sfu/Dockerfile`**: 多阶段构建（Go 1.24 → Alpine）
- **`sfu/go.mod`**: pion/webrtc v4 + pion/rtp

### 删除：LiveKit 全部依赖
- `livekit.yaml`、`livekit_api.py`、`ws_proxy.py`、`livekit_helpers.py`、`livekit-client.umd.min.js`

### 修改：Python 后端
- **`tab_publisher.py`**: 原生 WebRTC Publisher，导航时通过 WS 广播 `nav_start`/`nav_done` 事件
- **`tab_manager.py`**: 新增 viewer WS 注册/广播机制 + `create_tab()` 按需创建 tab
- **`ws.py`**: 支持双向 WS 通信（交互指令 + 服务端事件推送）
- **`app.py`**: 访问 `/viewer/{tab_id}` 时自动创建不存在的 tab，支持动态多标签

### 修改：前端 (`viewer.html`)
- 纯事件驱动 overlay：`nav_start` → 显示 loading，帧到达 → 隐藏
- 无帧轮询，无定时器触发 loading，静态页面完全不干扰
- 原生 `RTCPeerConnection`，ICE 断连自动重连

### Docker Compose
- `sfu` 服务 + `network_mode: "service:sfu"`
- 端口：`59055/udp+tcp`（ICE）、`8085`（HTTP）

## 导航切换流程

```
1. 用户点击链接 → Playwright framenavigated 事件
2. tab_publisher → WS 广播 nav_start → viewer 立即显示 loading
3. 0.3s debounce → publisher 重建 WebRTC → POST offer 到 SFU
4. SFU 收到新 publisher track → RTP rewriter 计算 seq/ts 偏移量
5. 新 RTP 数据写入同一 TrackLocalStaticRTP（序列号连续）
6. subscriber 的解码器无感知切换 → 新帧到达 → viewer 隐藏 loading
   （subscriber 全程保持同一 PeerConnection，零重连）
```

## 多标签支持

访问 `/viewer/tab_2`、`/viewer/tab_3` 等 URL 时自动创建新的浏览器标签页，每个 tab 有独立的 SFU room 和 Publisher。
