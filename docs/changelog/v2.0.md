# v2.0 — 用 Pion Go SFU 替换 LiveKit，彻底解决 Docker 下 WebRTC NAT 穿透

**日期**: 2026-04-08  
**分支**: `sfu-livekit`  

## 概要

彻底废弃 LiveKit Server，改用基于 [pion/webrtc](https://github.com/pion/webrtc) 的自建 Go SFU。采用与 [Neko](https://github.com/m1k1o/neko) 一致的 **ICE Lite + NAT 1:1 + UDPMux 单端口** 架构，完美兼容 Docker bridge 网络和路由器级代理，彻底终结了 LiveKit 在容器化环境下因 Full ICE 双向 STUN 检查失败导致的"viewer 永远 pending"问题。

## 为什么替换 LiveKit

| 问题 | LiveKit | Pion SFU (本版) |
|---|---|---|
| ICE 模式 | Full ICE（需双向连通） | ICE Lite（服务端被动响应） |
| Chrome mDNS 隐私 | 致命 — host candidate 被隐藏 | 无影响 — 不需要知道浏览器 IP |
| 路由器级代理 | srflx 不可达 → 断连 | 无影响 — 浏览器主动连服务端 |
| Docker bridge | 需要 hairpin NAT | 标准 DNAT 即可 |

## 变更明细

### 新增：Go SFU 服务 (`sfu/`)
- **`sfu/main.go`**: 完整的 pion/webrtc SFU，~290 行 Go 代码
  - ICE Lite 模式 — 服务端永远不主动发起 STUN 检查
  - NAT 1:1 映射 — 通过 `NAT_IP` 环境变量广播宿主机 IP 作为 ICE candidate
  - UDPMux 单端口 — 所有 PeerConnection 共享 `:59055` UDP 端口
  - HTTP 信令 — `POST /offer?room=xxx&role=pub|sub` 交换 SDP
  - PLI 自动注入 — subscriber 连接后立即向 publisher 请求关键帧
- **`sfu/Dockerfile`**: 多阶段构建（Go 1.24 → Alpine runtime）
- **`sfu/go.mod`**: pion/webrtc v4.2.11

### 删除：LiveKit 全部依赖
- **删除** `livekit.yaml` — LiveKit 服务器配置
- **删除** `tabshare/server/api/livekit_api.py` — Token 生成 API
- **删除** `tabshare/server/api/ws_proxy.py` — LiveKit WS 代理
- **删除** `tabshare/server/services/livekit_helpers.py` — LiveKit Token 工具
- **删除** `tabshare/server/static/vendor/livekit-client.umd.min.js` — LiveKit JS SDK

### 修改：Python 后端
- **`tab_publisher.py`**: 用原生 `RTCPeerConnection` + `getDisplayMedia()` 替换 LiveKit SDK 注入。Publisher 直接 POST SDP offer 到 `http://127.0.0.1:8088/offer`（共享网络命名空间）。
- **`app.py`**: 移除 LiveKit 路由，新增 `/api/sfu/offer` 代理路由（通过 httpx 转发到 Go SFU）。
- **`config.py`**: 移除 LiveKit 配置项，新增 `SFU_URL`。
- **`viewer.html`**: 用原生 `RTCPeerConnection` 替换 LiveKit JS SDK。Viewer 创建 recvonly offer → POST 到 `/api/sfu/offer` → 设置 SDP answer → ICE 自动连接。

### 修改：Docker Compose
- **替换** `livekit` 服务为 `sfu` 服务（自建镜像）
- **保持** `network_mode: "service:sfu"` — TabShare 与 SFU 共享网络命名空间
- **端口映射**: `59055:59055/udp+tcp`（ICE）、`8085:8085`（HTTP）

## 数据流

```
Publisher (容器内 Chromium):
  getDisplayMedia() → RTCPeerConnection
  POST offer → http://127.0.0.1:8088/offer?room=tab_1&role=pub
  ICE: STUN → 192.168.9.39:59055 → Docker DNAT → SFU ✅

Viewer (外部浏览器):
  POST offer → http://192.168.9.39:8085/api/sfu/offer?room=tab_1&role=sub
  ICE: STUN → 192.168.9.39:59055 → Docker DNAT → SFU ✅
```
